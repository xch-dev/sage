sage: scheme handler test page

Clicking a link below asks the OS to hand the URL to whatever app is registered for the sage: scheme (Sage in dev mode, or the installed build). See src/hooks/useDeepLink.ts for the parser this exercises. macOS only honors this from the bundled /Applications build — dev mode (pnpm tauri dev) will not receive it there. Replace the placeholder address/offer strings with real ones before testing.

Address deep link → /wallet/send/xch

Query params recognized: amount, fee (mojos, digits only), memos (note: NOT memo), asset_id (optional, 64 hex chars — a CAT asset id). Omit asset_id to send XCH; a wallet that doesn't hold the given asset shows an error toast instead of navigating.

Offer deep link → /offers/view/<offer>

Payload must match offer1[a-z0-9]+ and ≤ 15000 chars. Query param recognized: fee.

Error cases

These should each surface a toast in Sage rather than navigating anywhere.

Unrecognized payload Wrong scheme (browser will likely just no-op) Well-formed asset_id, not in wallet
